## 详细

### 概念
NoSQL（Not Only SQL）是一类非关系型数据库的统称，它不遵循传统的关系模型（二维表），数据存储格式灵活多样，通常面向水平扩展和高性能设计，常用于处理大规模数据和高并发访问场景。

### 重点

#### 一、四大类型对比

| 类型 | 数据模型 | 代表产品 | 最佳场景 |
| :--- | :--- | :--- | :--- |
| **键值存储** | Key-Value 结构 | Redis、Memcached、Riak | 缓存、会话管理、计数器 |
| **文档存储** | JSON / BSON 文档 | MongoDB、Elasticsearch、Firestore | 内容管理、日志、电商商品 |
| **列族存储** | 宽表 + 列簇 | HBase、Cassandra、BigTable | 大数据分析、时序数据、IoT |
| **图数据库** | 节点 + 边 + 属性 | Neo4j、JanusGraph、ArangoDB | 社交网络、推荐引擎、知识图谱 |

#### 二、核心特征

- **灵活的数据模型**：无需预定义 Schema，支持动态添加字段
- **水平扩展**：天然支持分布式集群，通过分片（Sharding）分担数据压力
- **高性能**：针对特定场景优化（如 Redis 内存读写、Cassandra 高吞吐写入）
- **弱一致性**：通常遵循 BASE 理论（基本可用、软状态、最终一致性），而非 ACID

#### 三、与关系型数据库对比

| 对比项 | 关系型（SQL） | 非关系型（NoSQL） |
| :--- | :--- | :--- |
| 数据模型 | 固定表结构 | 灵活格式（键值/文档/图等） |
| 事务支持 | ACID 强一致性 | BASE 最终一致性 |
| 扩展方式 | 垂直扩展为主 | 水平扩展为主 |
| 查询能力 | SQL 复杂关联查询 | 受限查询（按 Key 或简单条件） |
| 适用场景 | 核心业务数据 | 缓存、日志、分析、社交 |

#### 四、常见误区

- NoSQL 并不完全排斥 SQL，部分产品（如 MongoDB）已支持类似 SQL 的查询语法
- NoSQL 并非万能，事务一致性要求高的场景（如金融）仍需关系型数据库
- 实际项目中常采用混合架构：MySQL 存核心数据 + Redis 做缓存 + Elasticsearch 做搜索
