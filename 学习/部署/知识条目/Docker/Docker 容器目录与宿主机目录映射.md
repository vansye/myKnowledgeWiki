## 详细

### 概念
Bind Mount 是将宿主机上的一个目录或文件挂载到容器内部指定路径的机制。容器内对该路径的读写操作会直接反映到宿主机目录上，反之亦然，实现双向实时同步。

### 重点
- **本质**：宿主机目录与容器目录建立关联，两者指向同一份数据
- **适用场景**：
  - 开发环境：挂载源码目录，实现代码热加载（修改即生效）
  - 配置文件动态注入：将宿主机配置文件挂入容器覆盖默认配置
  - 日志收集：容器日志写入宿主机目录，供外部工具采集
- **基本语法**：
  - `-v /宿主机路径:/容器路径`（旧语法）
  - `--mount type=bind,source=/宿主机路径,target=/容器路径`（推荐语法）
- **示例**：`docker run -v $(pwd):/app -w /app node npm start`
- **与 Volume 的区别**：
  - Bind Mount：需指定宿主机绝对路径，直接访问宿主机文件系统
  - Volume：由 Docker 管理存储位置（`/var/lib/docker/volumes/`）
- **注意事项**：
  - 宿主机路径需使用**绝对路径**（`$(pwd)` 可获取当前目录）
  - 容器内目录会被宿主机目录内容**覆盖**（非合并）
  - 挂载后容器内该路径下的原有文件将不可见
  - 宿主机目录不存在时 Docker 会自动创建（仅限 `-v` 语法）
  - 文件权限问题：容器内进程可能无权限读写宿主机目录（需关注 UID/GID）
