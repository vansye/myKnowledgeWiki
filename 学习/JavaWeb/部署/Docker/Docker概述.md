## 一、什么是 Docker

Docker 是一个开源的容器化平台，核心思想是把应用和它运行所需的一切（代码、运行时、系统工具、库、配置文件）打包成一个**镜像（Image）**，然后从这个镜像运行出一个个**容器（Container）**。

```
代码 + 依赖 + 运行时 + 配置 → 镜像（只读的模板）
镜像 → 运行 → 容器（正在运行的实例）
```

**一句话总结**：Docker 让应用在任何装了 Docker 的机器上，以完全相同的方式运行。

---

## 二、核心概念

### 1. 镜像（Image）

- 只读的模板，包含运行应用所需的全部文件和配置
- 类似"类"，可以通过分层结构复用基础镜像
- 命令：`docker images` 查看本地镜像，`docker pull nginx` 拉取镜像

### 2. 容器（Container）

- 镜像的运行实例，是独立隔离的运行环境
- 启动、停止、删除都很轻量（秒级）
- 命令：`docker run nginx` 启动容器，`docker ps` 查看运行中的容器

### 3. 仓库（Registry）

- 存放镜像的仓库，类似代码的 Git 仓库
- 公共仓库：Docker Hub（docker.io）
- 私有仓库：公司内部搭建，用于存放自己的镜像
- 命令：`docker push` 上传，`docker pull` 下载

## 三、为什么需要 Docker

### 没有 Docker 时的痛点

```
"在我电脑上能跑啊！"
```

| 问题 | 说明 |
|------|------|
| **环境不一致** | 开发用 Java 17，测试用 Java 11，线上又不同 |
| **依赖冲突** | 项目 A 需要 MySQL 5.7，项目 B 需要 MySQL 8.0，装不下 |
| **部署繁琐** | 新服务器要装一堆软件，配置容易漏项 |
| **扩容困难** | 要跑多个实例就得开多台虚拟机，成本高 |

### Docker 如何解决

- 镜像把环境打包在一起，到哪都一样
- 多个容器可以跑不同版本，互不干扰
- 一条命令启动，秒级拉起
- 容器极轻量，一台服务器可以跑几十个容器

## 四、Docker vs 虚拟机

| 对比项 | 虚拟机（VM） | Docker 容器 |
|--------|------------|-----------|
| 重量 | 重（GB 级） | 轻（MB 级） |
| 启动时间 | 分钟级 | 秒级 |
| 隔离性 | 完整 OS 隔离 | 进程级隔离（足够） |
| 资源占用 | 每个 VM 独占内核 | 共享宿主机内核 |
| 磁盘占用 | 大（每个 VM 有完整 OS） | 小（共用基础镜像层） |
| 适用场景 | 运行不同操作系统 | 运行同一 OS 的多个应用 |

> **简单理解**：虚拟机是"一台完整的电脑"，容器是"一个进程被隔离起来了"。

---

## 小结

1. **Docker = 镜像 + 容器 + 仓库**，三件套即可上手
2. **镜像是模板，容器是实例**，一个镜像可以跑多个容器
3. **核心价值**：解决"环境不一致"问题，实现一致性的构建、测试、部署
4. **比虚拟机轻很多**：共享内核、秒级启动、MB 级占用
5. 学习 Docker 不必一次学全，先掌握 `docker run`、`docker ps`、`docker images` 三个命令就能开始用了
