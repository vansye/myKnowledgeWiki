## 详细

### 概念
前后端分离是指将 Web 应用的前端（用户界面、交互逻辑）与后端（业务逻辑、数据处理）完全分开，通过 HTTP/HTTPS 接口（通常是 [[Restful规范]] 定义的 RESTful API 或 GraphQL）进行数据交互的开发模式。前端和后端作为独立项目独立开发、独立部署。

### 重点
- **核心交互**：前端通过 Ajax/Fetch 请求后端 API，后端返回 JSON/XML 数据，前端负责渲染页面，后端不再控制视图层（如 JSP）。前后端通过 [[HTTP请求]] 和 [[HTTP响应]] 进行数据交换。
- **开发流程**：
  1. 需求评审与拆分
  2. **接口设计（契约先行）**：前后端共同定义 API 文档（入参、出参、路径、方法），这是联调的基础，遵循 [[Restful规范]]
  3. 并行开发：前端依据接口文档使用 Mock 数据（如 Mock.js）模拟后端，后端实现真实接口逻辑
  4. 接口联调：前后端环境打通，对接真实数据并修复问题，前端使用 [[API接口封装]] 管理请求
  5. 集成测试与独立部署（前端部署 Nginx/CDN，后端部署服务器）
- **核心工具**：API 文档管理（Swagger/OpenAPI、YApi、Apifox）、接口调试（Postman）、Mock 数据（Mock.js）
- **跨域问题**：分离模式下前端域和后端域不同，需配置 CORS（跨域资源共享）或使用 Nginx 反向代理解决
- **优点**：职责边界清晰，并行开发效率高，前端可 CDN 加速，后端可独立水平扩展
