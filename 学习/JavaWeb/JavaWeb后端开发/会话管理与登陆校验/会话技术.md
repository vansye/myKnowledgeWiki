## 什么是会话

> 用户打开浏览器，访问 Web 服务器，到关闭浏览器的整个过程，称为**一次会话**。

HTTP 协议是**无状态**的——它不会记住你上一次请求做了什么。为了让服务器能够"认出"同一个用户（例如：登录后访问其他页面不需要再次登录），需要使用**会话跟踪技术**来维护用户的状态。

常见的三种会话跟踪技术：

| 技术 | 数据存储位置 | 状态 | 典型场景 |
|------|--------------|------|----------|
| **Cookie** | 浏览器（客户端） | 有状态 | 记住登录名、购物车、偏好设置 |
| **Session** | 服务器 | 有状态 | 传统 Web 项目的用户登录状态 |
| **JWT** | 浏览器（通常存 Header/LocalStorage） | 无状态 | 分布式系统、前后端分离、移动端、API 鉴权 |

### 基本概念
**Cookie 是服务器发送到用户浏览器并保存在本地的一小块文本数据**。浏览器下次访问同一服务器时，会自动在请求头中携带这些 Cookie，服务器据此识别用户。

Cookie 由 **服务器创建 → 通过响应头 `Set-Cookie` 发送给浏览器 → 浏览器自动保存 → 下次请求时自动携带**。

### 工作流程

```
① 浏览器 → POST /login (username=admin, password=123456) → 服务器
                                                           │
② 服务器验证成功，创建 Cookie                               │
   Response Header:                                        │
   Set-Cookie: username=admin                              │
   Set-Cookie: loginTime=2026-07-17                        ▼

③ 浏览器 ← 响应 + Cookie（浏览器将 Cookie 保存到本地）
   ┌─────────────────────────────────────────┐
   │ 浏览器本地存储 Cookie                     │
   │ name=admin                              │
   │ loginTime=2026-07-17                    │
   └─────────────────────────────────────────┘

④ 浏览器再次请求其他页面（Cookie 自动携带）
   GET /index
   Cookie: username=admin; loginTime=2026-07-17
   → 服务器识别出"这是 admin 用户"
```

### Cookie 的常用属性

| 属性 | 说明 |
|------|------|
| `name=value` | Cookie 的键和值，必须 |
| `maxAge` | 最大存活时间（秒）。正数→持久化到磁盘；零或负数→关闭浏览器失效 |
| `path` | 哪些路径能拿到 Cookie（`/` 表示整个网站都能访问） |
| `domain` | 哪些域名能拿到 Cookie（跨域共享时使用） |
| `HttpOnly` | 禁止 JavaScript 读取，防止 XSS 攻击 |
| `Secure` | 只在 HTTPS 连接中传输 |

### Servlet 中操作 Cookie

```java
// ===== 写入 Cookie =====
Cookie cookie = new Cookie("username", "admin");
cookie.setMaxAge(60 * 60 * 24 * 7); // 7 天
cookie.setPath("/");
response.addCookie(cookie);

// ===== 读取 Cookie =====
Cookie[] cookies = request.getCookies();
if (cookies != null) {
    for (Cookie c : cookies) {
        if ("username".equals(c.getName())) {
            String value = c.getValue();
        }
    }
}

// ===== 删除 Cookie（通过 maxAge=0 覆盖） =====
Cookie cookie = new Cookie("username", "");
cookie.setMaxAge(0);
response.addCookie(cookie);
```

### Cookie 的优缺点

| 优点 | 缺点 |
|------|------|
| 服务器无负担，数据存客户端 | Cookie 容量有限（单条约 4KB） |
| 可以持久化，关闭浏览器后仍有效 | 明文传输，易被截获篡改（除非用 HttpOnly + Secure + HTTPS） |
| 使用简单，浏览器自动携带 | 跨域携带需要特殊配置（SameSite 属性） |

## Session

### 基本概念
**Session 是服务器端为每个用户创建的会话对象**。每个用户会获得一个唯一的 `sessionId`，这个 ID 通过 Cookie 传给浏览器，用户后续请求携带它，服务器据此找到对应 Session 对象。

Session 将数据保存在**服务器内存或持久化存储**中，浏览器只保存一个 `sessionId`（通常叫 `JSESSIONID`）。

### 工作流程

```
① 用户首次访问
   GET /login → 服务器
                │
                ▼
              生成一个新的 HttpSession
              sessionId = "A1B2C3D4..."
              在内存中： A1B2C3D4 → { username:"admin", role:"admin" }
                │
                ▼
② 响应中写入 Cookie
   Set-Cookie: JSESSIONID=A1B2C3D4...; Path=/

③ 浏览器保存 JSESSIONID（内存 Cookie，关闭浏览器即失效）

④ 用户访问其他页面
   GET /user/info
   Cookie: JSESSIONID=A1B2C3D4...
   → 服务器根据 ID 找到 Session，取出数据

⑤ 用户关闭浏览器
   → JSESSIONID 丢失（因为是内存 Cookie）
   → Session 仍在服务器，超时（默认 30 分钟）后被回收
```

### Servlet 中操作 Session

```java
// ===== 获取/创建 Session =====
// true：不存在则创建新的；false：不存在返回 null
HttpSession session = request.getSession(true);

// ===== 写入数据 =====
session.setAttribute("username", "admin");
session.setAttribute("role", "admin");
session.setAttribute("loginTime", LocalDateTime.now());

// ===== 读取数据 =====
String username = (String) session.getAttribute("username");

// ===== 删除数据 =====
session.removeAttribute("role");

// ===== 使 Session 失效（退出登录）=====
session.invalidate();

// ===== 设置超时（分钟）=====
// 方式1：代码
session.setMaxInactiveInterval(60 * 30); // 30 分钟

// 方式2：web.xml 全局配置
// <session-config>
//     <session-timeout>30</session-timeout>
// </session-config>
```

### Session 的优缺点

| 优点 | 缺点 |
|------|------|
| 数据存在服务器，相对安全 | 占用服务器内存，用户量大会影响性能 |
| 使用简单，开箱即用 | 分布式环境麻烦：多台服务器需要 Session 共享（Session 复制 / Redis 存储 / 粘性会话） |
| 能存任意类型对象（不仅是字符串） | 依赖 Cookie，浏览器禁用 Cookie 后要改用 URL 重写 |

### Cookie 和 Session 的关系

```
Session 的底层依赖 Cookie：

 服务器内存                浏览器
┌───────────────┐        ┌─────────────────────┐
│ Session Map   │        │ Cookie:              │
│ A1B2C3 → {... │  ←──── │  JSESSIONID=A1B2C3  │
│ X5Y6Z7 → {... │        │                      │
└───────────────┘        └─────────────────────┘
        ↑                           │
        │   取出数据（服务端）       │  自动携带（每次请求）
        │                           │
   ┌─────────────────────────────────────┐
   │  服务器根据 JSESSIONID 找到 Session  │
   └─────────────────────────────────────┘
```

## JWT（令牌技术）

### 基本概念
**JWT（JSON Web Token）是一种跨域认证的解决方案，是一段加密的字符串令牌**，由三部分组成：`Header.Payload.Signature`。

它是**无状态**的——服务器不需要保存用户数据，每次请求只要验证 Token 的签名就能确认用户身份。非常适合前后端分离、分布式、微服务场景。

### JWT 的结构

```
JWT = Base64Url(Header) + "." + Base64Url(Payload) + "." + HMAC(Signature)

例：
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9        ← Header（声明算法+类型）
.
eyJ1c2VybmFtZSI6ImFkbWluIiwiaWQiOjEsImV4cCI6MTUxNjIzOTAyMn0   ← Payload（用户数据+过期时间）
.
Hl1bGkE2hPVqkX3mT8qZ9k0p3d2k0v0n2b4c5d6e7f8    ← Signature（签名，防篡改）
```

**三段解析：**

| 部分 | 内容示例（JSON） | 说明 |
|------|-----------------|------|
| Header | `{ "alg":"HS256", "typ":"JWT" }` | 签名算法和令牌类型 |
| Payload | `{ "id":1, "username":"admin", "exp":1516239022 }` | 数据主体（**不能放密码等敏感信息**，只是 Base64 编码，不是加密） |
| Signature | `HMACSHA256(base64Url(header)+"."+base64Url(payload), secret)` | 用密钥签名，**防止篡改** |

### JWT 工作流程（登录场景）

```
① 登录请求
   POST /login  {"username":"admin","password":"123456"}  → 服务器
                                                                 │
② 验证用户名密码成功                                            │
   ┌────────────────────────────────────────────┐               │
   │  1. 查询数据库                              │               │
   │  2. 正确：生成 JWT Token（含 id、username）│               │
   │  3. 把 Token 放入响应体                     │               ▼
   └────────────────────────────────────────────┘
   响应：{"code":1, "msg":"success", "data":{"id":1,"username":"admin","token":"eyJhbG...Af3f"}}

③ 前端保存 Token（localStorage / sessionStorage）

④ 后续请求 —— 前端手动把 Token 放到请求头
   GET /emps  (需要登录)
   Header:
     Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

⑤ 后端拦截器/过滤器校验 Token
   ┌────────────────────────────────────────────┐
   │  1. 读取请求头中的 Token                     │
   │  2. 用密钥验证签名是否合法                   │
   │  3. 检查是否过期                            │
   │  4. 合法：放行；非法：返回 401 未登录         │
   └────────────────────────────────────────────┘
```

### Java 中生成与解析 JWT（使用 jjwt 库）

```xml
<!-- pom.xml 引入依赖 -->
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt</artifactId>
    <version>0.9.1</version>
</dependency>
<dependency>
    <groupId>javax.xml.bind</groupId>
    <artifactId>jaxb-api</artifactId>
    <version>2.3.1</version>
</dependency>
```

```java
import io.jsonwebtoken.Claims;
import io.jsonwebtoken.Jwts;
import io.jsonwebtoken.SignatureAlgorithm;
import java.util.Date;
import java.util.HashMap;
import java.util.Map;

public class JwtUtils {

    // 密钥（生产环境应配置到环境变量/配置中心）
    private static final String SIGN_KEY = "my-secret-key-must-be-at-least-256-bits-long";
    // 有效期 1 小时（毫秒）
    private static final long EXPIRE_TIME = 1000 * 60 * 60;

    /**
     * 生成 JWT Token
     */
    public static String generateJwt(Map<String, Object> claims) {
        return Jwts.builder()
                .addClaims(claims)                                // 载荷数据
                .signWith(SignatureAlgorithm.HS256, SIGN_KEY)      // 签名算法+密钥
                .setExpiration(new Date(System.currentTimeMillis() + EXPIRE_TIME))
                .compact();
    }

    /**
     * 解析 JWT Token
     * @return 解析后的载荷（Claims 本质是 Map），抛出异常说明 Token 非法或过期
     */
    public static Claims parseJwt(String token) {
        return Jwts.parser()
                .setSigningKey(SIGN_KEY)
                .parseClaimsJws(token)
                .getBody();
    }

    // ========== 使用示例 ==========
    public static void main(String[] args) {
        // 登录成功 → 生成 Token
        Map<String, Object> claims = new HashMap<>();
        claims.put("id", 1);
        claims.put("username", "admin");
        String token = generateJwt(claims);
        System.out.println("Token: " + token);

        // 校验 Token（拦截器/过滤器中调用）
        try {
            Claims body = parseJwt(token);
            System.out.println("id = " + body.get("id"));
            System.out.println("username = " + body.get("username"));
            System.out.println("过期时间 = " + body.getExpiration());
        } catch (Exception e) {
            System.out.println("Token 非法或已过期");
        }
    }
}
```

### JWT 的优缺点

| 优点 | 缺点 |
|------|------|
| **无状态**，不需要在服务器保存会话，适合分布式/微服务 | Payload 只是 Base64 编码，**不能放敏感信息**（如密码） |
| 支持跨域、跨语言，适合移动端、前后端分离 | 一旦签发，在有效期内无法主动作废（除非有额外黑名单机制） |
| 不依赖 Cookie，天然支持移动端、小程序 | Token 体积比 Cookie 大，每次请求都要传输 |
| 数字签名防篡改 | 密钥泄露 = 全线失守，密钥管理非常关键 |

### JWT 注意事项

1. **Payload 不是加密**——只是 Base64 编码，前端能直接解码查看，**严禁放密码**
2. **必须用 HTTPS**——防止传输过程中被窃取
3. **设置合理的过期时间**——越短越安全
4. **密钥要够长**——HS256 至少 256 位（32 字节），生产环境不要硬编码
5. **刷新 Token 机制**——双 Token（Access Token 短 + Refresh Token 长）可改善体验

## 三者对比

| 维度 | Cookie | Session | JWT |
|------|--------|---------|-----|
| **数据存储** | 浏览器（客户端） | 服务器内存/数据库 | 浏览器（通常 localStorage） |
| **状态** | 有状态 | 有状态 | **无状态** |
| **安全性** | 中等（需 HttpOnly+Secure） | 较高（数据在服务器） | 较高（签名防篡改） |
| **分布式支持** | 差 | 较差（需要 Session 共享） | **优秀** |
| **跨域支持** | 需 SameSite 配置 | 依赖 Cookie | 天然支持 |
| **移动端** | 一般（受限于浏览器 Cookie 机制） | 较差 | **良好** |
| **使用复杂度** | 简单 | 简单 | 中等（需拦截器校验） |
| **典型应用** | 记住登录名、购物车 | 传统 Web 项目登录态 | 前后端分离、API、微服务 |

### 选择建议

- **单体 Web 项目 + 传统页面** → Session（最省心）
- **需要记住简单偏好（非登录态）** → Cookie
- **前后端分离 / 多端 / 分布式 / API 鉴权** → **JWT**（推荐，也是你现在项目用的方案）


## 小结

- **Cookie**：客户端存储，小而简，适合持久化非敏感数据
- **Session**：服务端存储，配合 Cookie 传 ID，适合单体项目登录态
- **JWT**：无状态令牌，数字签名防篡改，适合前后端分离、分布式场景

## ThreadLocal（请求上下文传递）

当登录校验完成后，通常会把当前用户信息保存到 `ThreadLocal` 中。  
这样后面的控制器和业务层就能直接读取当前用户，而不用层层传参。

更详细的说明见 **ThreadLocal 技术笔记**。

掌握这三种会话技术，你就能应对 Web 开发中 99% 的用户身份识别场景！
