## 什么是分模块设计

分模块设计（多模块项目）是指**将一个大型项目拆分成多个独立的 Maven 模块**，每个模块负责不同的功能，通过模块间的依赖关系组合成完整的项目。

Maven 基础知识见 Maven。模块打包后的发布管理见 私服。

### 生活中的类比

想象你要建一栋房子：

- **不分模块**：一个人包揽所有活（打地基、砌墙、水电、装修）
- **分模块设计**：分工合作
  - 模块 A：打地基（基础模块）
  - 模块 B：砌墙（核心业务模块）
  - 模块 C：水电安装（工具模块）
  - 模块 D：装修（Web 模块）
  - 父工程：总指挥，统一管理材料标准和预算

每个模块可以独立开发、测试、打包，最后组合在一起。

## 为什么要分模块

### 单模块项目的问题

当项目变大后，所有代码堆在一个模块里会出现：

| 问题 | 表现 |
|------|------|
| **代码混乱** | 几百个类混在一起，分不清哪些是工具类、哪些是业务类 |
| **依赖冲突** | 所有依赖都堆在一个 pom.xml 里，版本管理困难 |
| **复用困难** | 想复用某个功能（如工具类），只能复制整个项目 |
| **编译缓慢** | 改一行代码要重新编译整个项目 |
| **团队协作冲突** | 多人改同一个模块，代码冲突频繁 |

### 分模块设计的好处

| 好处 | 说明 |
|------|------|
| **职责清晰** | 每个模块有明确的职责，如 pojo、service、web |
| **依赖管理** | 父工程统一管理依赖版本，避免冲突 |
| **模块复用** | 工具模块可以被多个项目复用 |
| **按需编译** | 只编译修改的模块，提升效率 |
| **团队协作** | 不同人负责不同模块，减少冲突 |
| **灵活打包** | 可以单独打包某个模块（如只打包 jar 给后端，不打包 web 模块） |

## 核心概念：聚合、继承、依赖传递

### 1. 聚合（Aggregation）

**聚合**是指父工程将多个子模块组织在一起，统一管理构建过程。

#### 在父工程的 pom.xml 中声明子模块

```xml
<project>
    <groupId>com.itheima</groupId>
    <artifactId>tlias-parent</artifactId>
    <version>1.0</version>
    <packaging>pom</packaging>  <!-- 父工程的打包方式必须是 pom -->
    
    <!-- 声明所有子模块 -->
    <modules>
        <module>tlias-pojo</module>
        <module>tlias-service</module>
        <module>tlias-web</module>
    </modules>
</project>
```

**要点：**

- `<packaging>pom</packaging>`：父工程不写代码，只管理子模块，打包类型必须是 pom
- `<modules>`：列出所有子模块的目录名（不是 artifactId，是文件夹名）
- 构建父工程时，会自动构建所有子模块（执行 `mvn install` 会按依赖顺序编译打包）

### 2. 继承（Inheritance）

**继承**是指子模块可以继承父工程的配置，避免重复写相同的依赖版本、插件配置等。

#### 父工程中统一管理依赖版本

```xml
<project>
    <groupId>com.itheima</groupId>
    <artifactId>tlias-parent</artifactId>
    <version>1.0</version>
    <packaging>pom</packaging>
    
    <!-- 统一管理依赖版本 -->
    <properties>
        <mysql.version>8.0.30</mysql.version>
        <mybatis.version>3.0.2</mybatis.version>
    </properties>
    
    <!-- dependencyManagement：只管理版本，不真正引入依赖 -->
    <dependencyManagement>
        <dependencies>
            <dependency>
                <groupId>mysql</groupId>
                <artifactId>mysql-connector-java</artifactId>
                <version>${mysql.version}</version>
            </dependency>
            <dependency>
                <groupId>org.mybatis</groupId>
                <artifactId>mybatis</artifactId>
                <version>${mybatis.version}</version>
            </dependency>
        </dependencies>
    </dependencyManagement>
</project>
```

#### 子模块继承父工程

```xml
<project>
    <!-- 声明父工程 -->
    <parent>
        <groupId>com.itheima</groupId>
        <artifactId>tlias-parent</artifactId>
        <version>1.0</version>
        <relativePath>../pom.xml</relativePath>  <!-- 父工程 pom 的相对路径 -->
    </parent>
    
    <artifactId>tlias-pojo</artifactId>
    
    <!-- 引入依赖时不需要写版本号，从父工程继承 -->
    <dependencies>
        <dependency>
            <groupId>mysql</groupId>
            <artifactId>mysql-connector-java</artifactId>
            <!-- 不需要写 version，父工程已经管理了 -->
        </dependency>
    </dependencies>
</project>
```

**要点：**

- `<parent>`：声明父工程，`<relativePath>` 指向父工程的 pom.xml
- `<dependencyManagement>`：父工程中用来**统一管理版本**，子模块引入时可以不写版本号
- 继承的不只是依赖，还有插件配置、properties 等

### 3. 依赖传递（Dependency Transitivity）

**依赖传递**是指模块 A 依赖模块 B，模块 B 依赖模块 C，那么模块 A 会自动获得模块 C 的依赖。

#### 依赖传递示例

```
tlias-web 依赖 tlias-service
tlias-service 依赖 tlias-pojo

结果：tlias-web 自动拥有 tlias-pojo 的类
```

**要点：**

- 依赖传递让模块间的依赖关系更简洁
- 只需要显式声明直接依赖，间接依赖会自动传递
- 可以在父工程中用 `<dependencyManagement>` 统一管理传递依赖的版本

## 父工程与子模块的关系

### 父工程的职责

| 职责 | 说明 |
|------|------|
| **统一管理版本** | 通过 `<dependencyManagement>` 锁定所有依赖的版本 |
| **统一插件配置** | 如编译插件、打包插件，子模块继承后不用重复写 |
| **聚合构建** | 构建父工程时自动构建所有子模块 |
| **共享 properties** | 定义公共的配置属性，如编码格式、JDK 版本等 |

### 子模块的职责

| 职责 | 说明 |
|------|------|
| **声明父工程** | 通过 `<parent>` 继承父工程的配置 |
| **引入具体依赖** | 在 `<dependencies>` 中引入本模块需要的依赖 |
| **编写业务代码** | 每个模块有自己的 src/main/java 和 src/main/resources |
| **独立打包** | 可以单独打包成 jar 或 war |

### 父工程的 pom.xml 完整示例

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 
         http://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <groupId>com.itheima</groupId>
    <artifactId>tlias-parent</artifactId>
    <version>1.0</version>
    <packaging>pom</packaging>

    <!-- 声明子模块 -->
    <modules>
        <module>tlias-pojo</module>
        <module>tlias-service</module>
        <module>tlias-web</module>
    </modules>

    <!-- 统一管理版本 -->
    <properties>
        <maven.compiler.source>17</maven.compiler.source>
        <maven.compiler.target>17</maven.compiler.target>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
        <mysql.version>8.0.30</mysql.version>
        <mybatis.version>3.0.2</mybatis.version>
        <pagehelper.version>1.4.6</pagehelper.version>
        <spring.boot.version>3.0.6</spring.boot.version>
    </properties>

    <!-- 统一管理依赖版本 -->
    <dependencyManagement>
        <dependencies>
            <!-- MySQL 驱动 -->
            <dependency>
                <groupId>mysql</groupId>
                <artifactId>mysql-connector-java</artifactId>
                <version>${mysql.version}</version>
            </dependency>

            <!-- MyBatis -->
            <dependency>
                <groupId>org.mybatis</groupId>
                <artifactId>mybatis</artifactId>
                <version>${mybatis.version}</version>
            </dependency>

            <!-- 分页插件 -->
            <dependency>
                <groupId>com.github.pagehelper</groupId>
                <artifactId>pagehelper-spring-boot-starter</artifactId>
                <version>${pagehelper.version}</version>
            </dependency>

            <!-- SpringBoot 起步依赖 -->
            <dependency>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-starter-web</artifactId>
                <version>${spring.boot.version}</version>
            </dependency>
        </dependencies>
    </dependencyManagement>

</project>
```

### 子模块的 pom.xml 示例

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 
         http://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <!-- 声明父工程 -->
    <parent>
        <groupId>com.itheima</groupId>
        <artifactId>tlias-parent</artifactId>
        <version>1.0</version>
        <relativePath>../pom.xml</relativePath>
    </parent>

    <artifactId>tlias-pojo</artifactId>

    <!-- 引入本模块需要的依赖 -->
    <dependencies>
        <!-- 不需要写版本号，从父工程继承 -->
        <dependency>
            <groupId>mysql</groupId>
            <artifactId>mysql-connector-java</artifactId>
        </dependency>
    </dependencies>

</project>
```

## 模块间的依赖关系

### 典型的三层架构分模块

```
tlias-parent (父工程)
├── tlias-pojo    (实体类模块)
├── tlias-service (业务逻辑模块)
└── tlias-web     (Web 控制层模块)
```

### 依赖关系图

```
┌─────────────────┐
│   tlias-web     │  ← 依赖 service 和 pojo
│  (Controller)   │
└────────┬────────┘
         │ 依赖
         ▼
┌─────────────────┐
│ tlias-service   │  ← 依赖 pojo
│   (Service)     │
└────────┬────────┘
         │ 依赖
         ▼
┌─────────────────┐
│  tlias-pojo     │  ← 不依赖其他模块
│   (Entity)      │
└─────────────────┘
```

### 各模块的 pom.xml 配置

#### 1. pojo 模块（最底层，不依赖其他模块）

```xml
<project>
    <parent>
        <groupId>com.itheima</groupId>
        <artifactId>tlias-parent</artifactId>
        <version>1.0</version>
    </parent>
    
    <artifactId>tlias-pojo</artifactId>
    
    <dependencies>
        <!-- 只引入需要的工具类，如 lombok -->
        <dependency>
            <groupId>org.projectlombok</groupId>
            <artifactId>lombok</artifactId>
        </dependency>
    </dependencies>
</project>
```

#### 2. service 模块（依赖 pojo）

```xml
<project>
    <parent>
        <groupId>com.itheima</groupId>
        <artifactId>tlias-parent</artifactId>
        <version>1.0</version>
    </parent>
    
    <artifactId>tlias-service</artifactId>
    
    <dependencies>
        <!-- 依赖 pojo 模块 -->
        <dependency>
            <groupId>com.itheima</groupId>
            <artifactId>tlias-pojo</artifactId>
            <version>1.0</version>
        </dependency>
        
        <!-- 引入 MyBatis、Spring 等 -->
        <dependency>
            <groupId>org.mybatis</groupId>
            <artifactId>mybatis</artifactId>
        </dependency>
    </dependencies>
</project>
```

#### 3. web 模块（依赖 service 和 pojo）

```xml
<project>
    <parent>
        <groupId>com.itheima</groupId>
        <artifactId>tlias-parent</artifactId>
        <version>1.0</version>
    </parent>
    
    <artifactId>tlias-web</artifactId>
    
    <dependencies>
        <!-- 依赖 service 模块（会自动传递依赖 pojo） -->
        <dependency>
            <groupId>com.itheima</groupId>
            <artifactId>tlias-service</artifactId>
            <version>1.0</version>
        </dependency>
        
        <!-- 引入 SpringBoot Web 起步依赖 -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-web</artifactId>
        </dependency>
    </dependencies>
    
    <!-- Web 模块需要打包成可执行的 jar -->
    <build>
        <plugins>
            <plugin>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-maven-plugin</artifactId>
            </plugin>
        </plugins>
    </build>
</project>
```

### 依赖传递的效果

在 web 模块中：

- 显式依赖 `tlias-service`
- `tlias-service` 依赖 `tlias-pojo`
- 结果：web 模块**自动拥有** pojo 模块的所有类，不需要再显式声明依赖 pojo

## 实际项目结构示例

### 目录结构

```
tlias-parent/                  ← 父工程根目录
├── pom.xml                    ← 父工程的 pom
├── tlias-pojo/                ← pojo 子模块
│   ├── pom.xml
│   └── src/
│       └── main/
│           └── java/
│               └── com/itheima/pojo/
│                   ├── Emp.java
│                   └── Dept.java
├── tlias-service/             ← service 子模块
│   ├── pom.xml
│   └── src/
│       └── main/
│           └── java/
│               └── com/itheima/service/
│                   ├── EmpService.java
│                   └── impl/
│                       └── EmpServiceImpl.java
└── tlias-web/                 ← web 子模块
    ├── pom.xml
    └── src/
        └── main/
            ├── java/
            │   └── com/itheima/controller/
            │       └── EmpController.java
            └── resources/
                └── application.yml
```

### 构建顺序

当在父工程根目录执行 `mvn clean install` 时，Maven 会：

1. 先构建 `tlias-pojo`（没有依赖其他模块）
2. 再构建 `tlias-service`（依赖 pojo）
3. 最后构建 `tlias-web`（依赖 service）

Maven 会自动分析依赖关系，按正确的顺序构建。

## 分模块设计的最佳实践

### 1. 模块划分原则

| 模块类型 | 职责 | 示例 |
|----------|------|------|
| **pojo / entity** | 实体类、DTO、VO | Emp, Dept, Result |
| **common / utils** | 工具类、常量、异常定义 | JwtUtils, DateUtils |
| **dao / mapper** | 数据访问层 | EmpMapper, DeptMapper |
| **service** | 业务逻辑层 | EmpService, EmpServiceImpl |
| **web / controller** | 控制层、接口 | EmpController |

### 2. 依赖方向原则

```
正确：web → service → pojo
      （上层依赖下层，下层不依赖上层）

错误：pojo → service → web
      （下层依赖上层会导致循环依赖）
```

**要点：**

- 依赖方向必须**单向**，不能循环
- 底层模块（如 pojo）不应该知道上层模块的存在
- 如果 pojo 需要用到 service 的功能，说明模块划分有问题

### 3. 父工程的管理

- 所有版本统一的依赖都放在父工程的 `<dependencyManagement>` 中
- 子模块引入依赖时**不写版本号**
- 公共的插件配置也放在父工程中

### 4. 打包方式

| 模块 | 打包方式 | 说明 |
|------|----------|------|
| 父工程 | `pom` | 只管理子模块，不打包 |
| pojo / service / common | `jar` | 作为依赖被其他模块引用 |
| web | `jar` 或 `war` | 最终可执行的模块 |

### 5. 避免过度拆分

- 小项目不需要分太多模块，2-3 个即可
- 只有当代码量变大、团队协作需要时才拆分
- 拆分粒度要合理，不要一个类一个模块

## 常见问题与解决方案

### 问题 1：子模块找不到父工程

**错误信息：**

```
Could not find artifact com.itheima:tlias-parent:pom:1.0
```

**原因：**

父工程还没有安装到本地仓库，子模块找不到它。

**解决方案：**

先在父工程根目录执行 `mvn install`，将父工程安装到本地仓库。

### 问题 2：循环依赖

**错误信息：**

```
The projects in the reactor contain a cyclic reference
```

**原因：**

模块 A 依赖模块 B，模块 B 又依赖模块 A，形成循环。

**解决方案：**

重新设计模块划分，确保依赖方向是单向的。

### 问题 3：依赖传递失效

**现象：**

web 模块依赖 service，但用不到 pojo 的类。

**可能原因：**

- pojo 模块没有正确安装到本地仓库
- service 模块的 pom 中没有正确声明依赖 pojo

**解决方案：**

1. 在父工程根目录执行 `mvn clean install`
2. 检查 service 模块的 pom.xml 是否正确依赖了 pojo

### 问题 4：版本冲突

**现象：**

运行时提示 `NoSuchMethodError` 或 `ClassNotFoundException`。

**原因：**

不同模块引入了同一个依赖的不同版本。

**解决方案：**

在父工程的 `<dependencyManagement>` 中统一锁定版本号。

## 小结

### 分模块设计的核心要点

| 要点 | 说明 |
|------|------|
| **聚合** | 父工程通过 `<modules>` 组织子模块，统一管理构建 |
| **继承** | 子模块通过 `<parent>` 继承父工程的配置，避免重复 |
| **依赖传递** | 模块 A 依赖 B，B 依赖 C，A 自动拥有 C 的依赖 |
| **父工程职责** | 统一版本管理、插件配置、聚合构建 |
| **依赖方向** | 上层依赖下层，下层不依赖上层，避免循环 |

### 口诀

**父工程管理版本，子模块来继承；  
聚合构建按顺序，依赖传递要单向。**

### 最容易混淆的两个点

- **`<dependencyManagement>` vs `<dependencies>`**：前者只管理版本不真正引入依赖，后者真正引入依赖
- **聚合 vs 继承**：聚合是父工程组织子模块的方式，继承是子模块复用父工程配置的机制

---

Maven 分模块设计的本质是：**通过模块拆分降低复杂度，通过聚合和继承实现统一管理，通过依赖传递简化模块间的依赖关系。**

掌握分模块设计，你就能管理大型项目，让代码结构更清晰、团队协作更高效！
