## 什么是私服

私服（Private Maven Repository）是**公司内部搭建的 Maven 仓库服务器**，用来存放和管理公司内部的 jar 包以及从中央仓库代理过来的第三方依赖。

### 生活中的类比

| 概念 | 类比 |
|------|------|
| **Maven 中央仓库** | 大型公共图书馆（所有人都能借书，但距离远、种类有限） |
| **私服** | 公司内部的资料室（只对公司员工开放，可以存放内部文档，也能代购外部书籍） |
| **本地仓库** | 你个人的书架（从图书馆或资料室借来的书放在这里） |

---

## 为什么需要私服

### 没有私服时的痛点

| 痛点 | 说明 |
|------|------|
| **内部 jar 共享困难** | 公司自己写的工具 jar，只能通过拷贝文件共享，版本混乱 |
| **重复下载** | 每个开发者都要从中央仓库下载同样的依赖，浪费带宽和时间 |
| **网络依赖** | 没有外网就无法构建项目 |
| **版本失控** | 第三方依赖版本各自为政，环境不一致 |
| **安全性差** | 内部代码无法安全地发布到公共仓库 |

### 私服的好处

| 好处 | 说明 |
|------|------|
| **内部共享** | 公司内部的 jar 统一发布到私服，所有人直接引用 |
| **代理缓存** | 私服代理中央仓库，下载过的依赖会缓存，速度更快 |
| **节省带宽** | 只需一个人从中央仓库下载，其他人从私服获取 |
| **版本统一** | 所有开发者从同一个私服获取依赖，环境一致 |
| **安全可控** | 内部 jar 不对外公开，权限可控 |
| **离线构建** | 私服缓存过的依赖，即使断网也能构建 |

## 私服的工作原理

### Maven 查找依赖的完整流程

```
项目需要某个依赖
        │
        ▼
① 查找本地仓库（~/.m2/repository）
        │
        ├── 找到 → 直接使用 ✓
        │
        └── 没找到 ↓
                │
                ▼
② 查找私服（如果配置了）
        │
        ├── 私服有缓存 → 下载到本地仓库 → 使用 ✓
        │
        └── 私服也没有 ↓
                │
                ▼
③ 私服代理去中央仓库下载
        │
        ├── 下载成功 → 缓存到私服 → 下载到本地仓库 → 使用 ✓
        │
        └── 下载失败 → 报错 ✗
```

### 要点

- **本地仓库优先**：Maven 总是先查本地，再查远程
- **私服是中间层**：介于本地仓库和中央仓库之间
- **缓存机制**：私服下载过的依赖会缓存，下次其他人直接获取
- **代理角色**：私服可以代理中央仓库，代替开发者去中央仓库下载

## Nexus 私服搭建

### 什么是 Nexus

Nexus 是 Sonatype 公司开发的 Maven 仓库管理工具，是最常用的私服解决方案。

### 安装步骤（简述）

1. 下载 Nexus：https://help.sonatype.com/repomanager3/download
2. 解压到任意目录
3. 运行 `bin/nexus.bat start`（Windows）或 `bin/nexus run`（Linux）
4. 访问 `http://localhost:8081`
5. 默认账号密码：`admin / admin123`

### 安装后的默认仓库

Nexus 安装后自带几个仓库：

| 仓库名 | 类型 | 说明 |
|--------|------|------|
| `maven-central` | proxy | 代理 Maven 中央仓库 |
| `maven-releases` | hosted | 存放正式版本的 jar |
| `maven-snapshots` | hosted | 存放快照版本（开发版）的 jar |
| `maven-public` | group | 分组仓库，聚合了上面三个 |

---

## Nexus 中的仓库类型

### 三种核心仓库类型

| 类型 | 说明 | 用途 |
|------|------|------|
| **hosted（宿主仓库）** | 存放公司自己发布的 jar | 存放内部开发的工具包、业务模块 |
| **proxy（代理仓库）** | 代理远程仓库（如中央仓库） | 缓存从中央仓库下载过的依赖 |
| **group（分组仓库）** | 聚合多个仓库 | 对外提供一个统一的下载地址 |

### 关系图

```
┌─────────────────────────────────────────┐
│           maven-public (group)          │
│     对外提供统一下载入口                  │
│                                         │
│   ┌─────────────┐  ┌────────────────┐  │
│   │maven-releases│  │maven-snapshots │  │
│   │  (hosted)    │  │   (hosted)     │  │
│   │  正式版本     │  │   快照版本      │  │
│   └─────────────┘  └────────────────┘  │
│                                         │
│   ┌─────────────────────────────────┐  │
│   │       maven-central (proxy)      │  │
│   │    代理 Maven 中央仓库            │  │
│   └─────────────────────────────────┘  │
└─────────────────────────────────────────┘
```

### 要点

- **hosted**：自己上传的 jar 放这里
- **proxy**：自动从中央仓库缓存，不需要手动上传
- **group**：把多个仓库打包成一个地址，配置 Maven 时只需要指向 group

## 在项目中配置私服

### 在 pom.xml 中配置私服地址

```xml
<project>
    ...
    
    <!-- 配置私服仓库 -->
    <repositories>
        <repository>
            <id>nexus-public</id>
            <name>Nexus Public Group</name>
            <url>http://192.168.1.100:8081/repository/maven-public/</url>
            <!-- 如果私服需要认证 -->
            <!--
            <releases>
                <enabled>true</enabled>
            </releases>
            <snapshots>
                <enabled>true</enabled>
            </snapshots>
            -->
        </repository>
    </repositories>
    
    <!-- 配置插件仓库（如果需要从私服下载插件） -->
    <pluginRepositories>
        <pluginRepository>
            <id>nexus-public</id>
            <name>Nexus Public Group</name>
            <url>http://192.168.1.100:8081/repository/maven-public/</url>
        </pluginRepository>
    </pluginRepositories>
    
</project>
```

### 在 settings.xml 中配置（推荐，全局生效）

在 `~/.m2/settings.xml` 中配置，所有项目都能用：

```xml
<settings>
    
    <!-- 配置私服认证信息 -->
    <servers>
        <server>
            <id>nexus-releases</id>
            <username>admin</username>
            <password>admin123</password>
        </server>
        <server>
            <id>nexus-snapshots</id>
            <username>admin</username>
            <password>admin123</password>
        </server>
    </servers>
    
    <!-- 配置镜像（让中央仓库的请求走私服） -->
    <mirrors>
        <mirror>
            <id>nexus-mirror</id>
            <mirrorOf>central</mirrorOf>
            <name>Nexus Mirror of Central</name>
            <url>http://192.168.1.100:8081/repository/maven-public/</url>
        </mirror>
    </mirrors>
    
    <!-- 配置 profile，让所有项目默认使用私服 -->
    <profiles>
        <profile>
            <id>nexus-profile</id>
            <repositories>
                <repository>
                    <id>nexus-public</id>
                    <url>http://192.168.1.100:8081/repository/maven-public/</url>
                    <releases>
                        <enabled>true</enabled>
                    </releases>
                    <snapshots>
                        <enabled>true</enabled>
                    </snapshots>
                </repository>
            </repositories>
        </profile>
    </profiles>
    
    <!-- 激活 profile -->
    <activeProfiles>
        <activeProfile>nexus-profile</activeProfile>
    </activeProfiles>
    
</settings>
```

### `<mirrorOf>` 的常见取值

| 值 | 含义 |
|----|------|
| `*` | 代理所有远程仓库 |
| `central` | 只代理中央仓库 |
| `*,!xxx` | 代理所有仓库，但排除 xxx |

## 将项目发布到私服

### 在 pom.xml 中配置发布地址

```xml
<project>
    
    <groupId>com.itheima</groupId>
    <artifactId>tlias-pojo</artifactId>
    <version>1.0</version>
    
    <!-- 配置发布到私服的地址 -->
    <distributionManagement>
        <!-- 正式版本发布到这里 -->
        <repository>
            <id>nexus-releases</id>
            <url>http://192.168.1.100:8081/repository/maven-releases/</url>
        </repository>
        <!-- 快照版本发布到这里 -->
        <snapshotRepository>
            <id>nexus-snapshots</id>
            <url>http://192.168.1.100:8081/repository/maven-snapshots/</url>
        </snapshotRepository>
    </distributionManagement>
    
</project>
```

### 要点

- `<distributionManagement>` 的 `<id>` 必须和 `settings.xml` 中 `<server>` 的 `<id>` 对应，才能匹配到认证信息
- 正式版本（如 `1.0`）发布到 `maven-releases`
- 快照版本（如 `1.0-SNAPSHOT`）发布到 `maven-snapshots`

### 执行发布命令

```bash
# 发布到私服
mvn deploy
```

### 发布流程

```
mvn deploy
    │
    ▼
① 编译、测试、打包
    │
    ▼
② 根据版本号判断发布到哪个仓库
    │
    ├── 版本号是 x.x（如 1.0）→ 发布到 maven-releases
    │
    └── 版本号带 SNAPSHOT（如 1.0-SNAPSHOT）→ 发布到 maven-snapshots
    │
    ▼
③ 根据 <id> 从 settings.xml 中找到对应的账号密码
    │
    ▼
④ 上传 jar 包和 pom 到私服
```

## 从私服下载依赖

### 其他项目引用已发布的 jar

```xml
<dependencies>
    <dependency>
        <groupId>com.itheima</groupId>
        <artifactId>tlias-pojo</artifactId>
        <version>1.0</version>
    </dependency>
</dependencies>
```

### 下载流程

```
项目构建，需要 com.itheima:tlias-pojo:1.0
        │
        ▼
① 查本地仓库 → 没有
        │
        ▼
② 查私服（maven-public）
        │
        ├── 私服有 → 下载到本地仓库 → 使用 ✓
        │
        └── 私服没有 → 去中央仓库找 → 找到后缓存到私服 → 下载到本地 → 使用 ✓
```

### 要点

- 只要私服配置正确，引用内部 jar 和引用第三方 jar 的体验完全一样
- 不需要手动拷贝 jar 文件，Maven 自动从私服下载

## 私服的分组与代理

### 分组仓库（Group Repository）

分组仓库把多个仓库聚合成一个地址，Maven 只需要配置一个 URL 就能访问多个仓库。

```
maven-public (group)
    ├── maven-releases (hosted)     ← 公司内部正式包
    ├── maven-snapshots (hosted)    ← 公司内部快照包
    └── maven-central (proxy)       ← 代理中央仓库
```

**好处：** Maven 只需要指向 `maven-public` 一个地址，就能同时获取内部 jar 和第三方 jar。

### 代理仓库（Proxy Repository）

代理仓库用来缓存远程仓库的内容。第一次从中央仓库下载某个依赖后，私服会缓存它，下次其他人再要这个依赖时直接从私服获取。

```
开发者 A 第一次请求 spring-core
        │
        ▼
私服没有缓存 → 去中央仓库下载 → 缓存到私服 → 返回给 A
        │
开发者 B 再请求 spring-core
        │
        ▼
私服有缓存 → 直接返回给 B（不需要再去中央仓库）
```

## 常见应用场景

### 场景 1：公司内部工具包共享

公司写了一个通用工具包 `common-utils`，多个项目都要用。

**做法：**

1. 在 `common-utils` 项目中配置 `<distributionManagement>` 指向私服
2. 执行 `mvn deploy` 发布到私服
3. 其他项目在 pom.xml 中直接引入 `common-utils` 的依赖

### 场景 2：多模块项目发布

父工程配置好 `<distributionManagement>`，子模块继承后，执行 `mvn deploy` 可以一次性把所有子模块发布到私服。

### 场景 3：代理中央仓库加速

通过配置 `<mirror>`，让所有对中央仓库的请求都走私服，利用私服的缓存加速下载。

### 场景 4：离线环境构建

在有网时先把需要的依赖同步到私服，之后在断网环境中也能通过私服构建项目。

## 常见问题与解决方案

### 问题 1：发布到私服时 401 Unauthorized

**原因：**

`settings.xml` 中 `<server>` 的 `<id>` 和 `pom.xml` 中 `<distributionManagement>` 的 `<id>` 不匹配。

**解决方案：**

确保两边的 `<id>` 完全一致。

### 问题 2：从私服下载依赖 404

**原因：**

- 依赖没有发布到私服
- 私服地址配置错误
- 仓库类型不对（如发布到 releases，但下载时指向 snapshots）

**解决方案：**

1. 登录 Nexus 确认 jar 是否存在
2. 检查 pom.xml 中的私服 URL
3. 确认版本号匹配（SNAPSHOT 版本要去 snapshots 仓库找）

### 问题 3：私服缓存了旧版本，更新不了

**原因：**

Maven 默认对 SNAPSHOT 版本有更新检查机制，但可能因为缓存策略导致不更新。

**解决方案：**

```bash
# 强制更新快照
mvn clean install -U
```

或者在仓库配置中设置：

```xml
<repository>
    <id>nexus-snapshots</id>
    <url>...</url>
    <snapshots>
        <enabled>true</enabled>
        <updatePolicy>always</updatePolicy>  <!-- 每次构建都检查更新 -->
    </snapshots>
</repository>
```

### 问题 4：Nexus 启动失败

**常见原因：**

- 端口 8081 被占用
- JDK 版本不兼容（Nexus 3.x 需要 JDK 8+）
- 内存不足

**解决方案：**

```bash
# 检查端口占用
netstat -ano | findstr 8081

# 修改端口：编辑 etc/nexus-default.properties
application-port=8082
```

## 小结

### 私服的核心要点

| 要点 | 说明 |
|------|------|
| **私服是什么** | 公司内部的 Maven 仓库服务器 |
| **为什么用** | 内部 jar 共享、代理缓存、节省带宽、版本统一 |
| **三种仓库** | hosted（自己上传）、proxy（代理远程）、group（聚合多个） |
| **发布到私服** | pom.xml 配置 `<distributionManagement>`，执行 `mvn deploy` |
| **从私服下载** | pom.xml 配置 `<repositories>` 或 settings.xml 配置 `<mirror>` |
| **认证配置** | settings.xml 中 `<server>` 的 `<id>` 要和 pom 中的 `<id>` 对应 |

### 口诀

**私服是中间层，代理缓存加速快；  
hosted 存内部，proxy 代外仓；  
deploy 往上发，build 往下拿；  
id 要对应，认证才能过。**

### 最容易混淆的两个点

- **`<repositories>` vs `<distributionManagement>`**：前者配置从哪里下载依赖，后者配置发布到哪里
- **`<mirror>` vs `<repository>`**：`<mirror>` 是镜像，会替换掉原来的仓库地址；`<repository>` 是新增一个仓库

---

Maven 私服的本质是：**在公司内部搭建一个仓库服务器，作为本地仓库和中央仓库之间的中间层，实现内部 jar 共享和外部依赖的代理缓存。**

掌握私服搭建和配置，你就能在公司项目中实现依赖的统一管理和高效共享！
